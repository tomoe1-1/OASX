# OASX 2.4.0 眼睛动画

主页背景与启动页的少女，从这一版起会**真正把眼睛睁开** —— 不再是整张图淡入淡出地切换，
而是眼睑本身沿着一条连续曲线抬起，睫毛跟着走。

## 效果

### 主页背景

一轮 18 秒，循环：

| 时间 | 动作 |
|---|---|
| 0 – 0.7 s | 闭眼静止（留一点停顿，避免一进界面就动） |
| 0.7 – 4.3 s | 缓慢睁开，3.6 秒 `easeInOutCubic` |
| 4.3 – 16.8 s | 保持睁开（12.5 秒，占一轮的 70%） |
| 16.8 – 18 s | 缓慢闭合，1.2 秒 |

之所以把睁开拉到 3.6 秒、并把睁着的时段拉到 12.5 秒：
界面是给正在看日志的人用的，眼睛是**背景里的呼吸**，不是主角。
动得太快会变成「一直在眨」，反而抢注意力。

开启系统「减少动态效果」时，直接停在**睁开**状态并保持静止 —— 内容正确，只去掉运动。

### 启动页

睁眼动画由独立的 controller 驱动，与进度解耦：

- **定时模式**：睁眼与整段开场动画同步推进。
- **任务模式**（真实启动流程）：此前 controller 不启动，`progress` 由外部任务驱动，
  眼睛会一直闭着直到进度走完；现在 controller 只负责眼睑，进度仍走外部任务。
- 收尾计时改为 `剩余动画时长 + 停留`，任务已失败时不再空等剩余时长。

## 实现：`EyeMotion`

`src/lib/utils/eye_motion.dart`

### 为什么要预渲染姿态图而不是画一个遮罩

一开始的自然想法是「在眼睛位置画一个肤色矩形当眼皮，往下移」。
实际效果是**一眼假**：睫毛、眼线的形状来自原画，遮罩画不出来；
而且眼皮边缘和周围皮肤/头发的接缝在放大后非常明显。

现在改成：美术侧提供 5 张姿态图（闭 / 四分之一 / 半 / 四分之三 / 睁），
代码只做「把带睫毛的那一条眼皮条带，从当前姿态的眼睑高度移动到目标高度」。

### 三个关键设计

**1. 单调 Hermite 插值（位置 + 速度都对得上）**

姿态图只有 5 张，直接线性插值会在姿态切换处出现「速度突变」——
表现为眼皮走到某个开度时顿一下。`lidHeight()` 用单调三次 Hermite，
在每个姿态点上同时约束**位置和切线斜率**，切线用 Fritsch–Carlson 权重
（`w1 = 2Δnext + Δprev`、`w2 = Δnext + 2Δprev`）算，保证不 overshoot：
眼皮永远不会「睁开过头再弹回来」。

**2. 网格变形而不是整体平移**

`_draw()` 用 `canvas.drawVertices` 画一个 4 行 × 17 列的网格：

- 第 0 行（patch 顶）与第 3 行（patch 底）**不动** —— 周围的头发和皮肤保持原样；
- 第 1、2 行是夹着当前眼睑高度的一条 ±4px 窄带，**整体移动到目标高度**；
- 横向按 `edge = 4u(1-u)` 加权 —— 中间移动最多、两端为 0，
  这样条带两端与不动的皮肤平滑接续，不会在眼角撕出一条直线。

相邻两个姿态之间按 `mix` 叠画两层，交叉淡入淡出，所以是连续过渡而不是跳帧。

**3. 共享一张眼睑位置**

两个相邻姿态的眼睑高度不同，但它们必须被拉到**同一个**目标高度。
所以 `paint()` 先算 `lidHeight(lid, opening)` 得到目标，
再把两个姿态分别变形到这个目标 —— 这才是「插值」而不是「叠影」。

### 启动页跳过一张重复图

启动页原本的「半睁」图和「四分之一睁」几乎一样，
留着会让眼睑在半途停住（两段插值的斜率都接近 0）。
`prepareSplash()` 显式跳过这张，只保留 4 个有效姿态。
