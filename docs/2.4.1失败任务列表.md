# 2.4.1 失败任务列表

失败任务队列从这一版起只显示**启用中**的任务。

## 行为

| 场景 | 2.4.0 及以前 | 2.4.1 |
|---|---|---|
| 失败任务被手动停用 | 仍占一行，标题计数 +1，行内显示「已停用，重试暂停 / 原重试时间」 | 不显示，标题计数不增加 |
| 数据层记录 | 保留 | 保留（不清空） |
| 重新启用 | —— | 回到列表，显示原重试时间 |
| 队列为空 | 显示「暂无失败任务」 | 显示「暂无失败任务」（口径为启用中的任务） |

## 为什么

停用的失败任务既不会自动重试，也不该占着「失败任务（N）」的计数 —— 看上去有失败任务、点进去却都点不动，属于误报。计数应该与「真正会重试的队列」一致。

## 实现

`src/lib/modules/home/widgets/task_status_panel.dart`：

```dart
// Keep paused records in the model, but exclude them from the retry queue.
final failedTasks = widget.scriptModel.failedTaskList
    .where((task) => task.enabled)
    .toList();
```

标题计数、空态判断、`itemCount`、逐项取值都改用这份过滤结果；原先 `retry.enabled` 的三元文案随之简化为「下次重试：X」（过滤后队列里只剩启用中的任务，不会再说错）。

`failedTaskList` 本身不做任何删除 —— 停用与启用是可逆的，记录必须留着，重新启用时能原样回到队列。

## 验证

`src/test/home_workbench_resize_test.dart`：停用任务不渲染（`findsNothing`）、标题显示「失败任务（0）」、列表显示「暂无失败任务」、`model.failedTaskList` 仍有该条记录；重新启用后回到列表并显示原重试时间；窄窗口（1000×700 / 700×600）下同样成立。
